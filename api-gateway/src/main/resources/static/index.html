How a request flows

  Client
    |  Authorization: Bearer <JWT>
    v
  API Gateway :8080
    |  validates the signature, rejects anything invalid with 401
    |  replaces client headers with X-User-Id / X-Username / X-User-Role
    |  resolves lb://trip-service through Eureka
    v
  Trip Service :8083
    |  trusts the gateway headers, enforces roles with @PreAuthorize
    |  needs the vehicle marked ON_TRIP
    |  calls vehicle-service by name over OpenFeign (no host, no port)
    v
  Vehicle Service :8082
       checks the status transition is legal, updates its own database

Domain model

EntityServiceKey fieldsStates
Vehiclevehicle-service vehicle_id, type, status, location AVAILABLE · ON_TRIP · UNDER_MAINTENANCE · OUT_OF_SERVICE
Triptrip-service trip_id, vehicle_id, driver_id, trip_status SCHEDULED · IN_PROGRESS · COMPLETED · CANCELLED
Maintenancemaintenance-service maintenance_id, vehicle_id, issue, status REPORTED · IN_REPAIR · RESOLVED · CANCELLED
Userauth-service user_id, username, password, role ADMIN · DISPATCHER · DRIVER

Each service owns its own schema. Cross-service references such as vehicle_id on a trip are plain columns, never JPA relationships — a trip reads vehicle data by calling vehicle-service, not by joining to it.
